## 🎯 概述

### 目标

将 Aura 项目从单体架构转换为模块化插件架构，实现：

- ✅ **编译时间减少 50%** - 模块独立编译
- ✅ **代码复用性提升** - 插件可独立使用
- ✅ **并行开发支持** - 团队成员可独立开发不同插件
- ✅ **维护性提升** - 清晰的模块边界

### 架构图

```
Aura 项目
├── Plugins/
│   ├── AuraCore/          (核心插件 - Week 5)
│   │   ├── 核心接口
│   │   ├── 工具类
│   │   ├── 基础类型
│   │   └── 公共组件
│   │
│   ├── AuraGAS/           (GAS 插件 - Week 6)
│   │   ├── AbilitySystemComponent
│   │   ├── AttributeSet
│   │   ├── GameplayAbilities
│   │   ├── GameplayEffects
│   │   └── 依赖: AuraCore
│   │
│   ├── AuraUI/            (UI 插件 - Week 7)
│   │   ├── WidgetController
│   │   ├── MVVM 组件
│   │   ├── UI 工具类
│   │   └── 依赖: AuraCore, AuraGAS
│   │
│   ├── AuraCharacter/     (角色插件 - Week 9)
│   │   ├── 角色基类
│   │   ├── 玩家角色
```

## 🏗️ 插件架构设计

### 插件标准结构

每个插件都遵循以下标准结构：

```
PluginName/
├── PluginName.uplugin          # 插件描述文件
├── Resources/
│   └── Icon128.png             # 插件图标
├── Source/
│   └── PluginName/
│       ├── PluginName.Build.cs # 构建配置
│       ├── Private/            # 私有实现
│       │   ├── PluginNameModule.cpp
│       │   └── ...
│       └── Public/             # 公共接口
│           ├── PluginNameModule.h
│           └── ...
└── Content/                    # 可选：蓝图资源
```

### 插件描述文件模板

```json
{
    "FileVersion": 3,
    "Version": 1,
    "VersionName": "1.0",
    "FriendlyName": "Plugin Name",
    "Description": "Plugin description",

    "CreatedByURL": "",
    "DocsURL": "",

    "SupportURL": "",
    "CanContainContent": true,
    "IsBetaVersion": false,
    "IsExperimentalVersion": false,
    "Installed": false,
    "Modules": [
        {
            "Name": "PluginName",
            "Type": "Runtime",
            "LoadingPhase": "Default"
        }
    ],
    "Plugins": []
}
```

## 📝 实施步骤

### 总体流程

1. **创建插件结构** - 创建插件目录和描述文件
2. **配置构建系统** - 设置 Build.cs 和依赖关系
3. **迁移代码** - 将代码从主项目迁移到插件
4. **更新引用** - 修改 include 路径和模块依赖
5. **编译测试** - 确保插件独立编译成功
6. **功能测试** - 验证所有功能正常工作
7. **文档更新** - 更新相关文档

### 迁移原则

#### ✅ DO（应该做的）

- ✅ 保持文件结构清晰
- ✅ 遵循 UE5 命名规范
- ✅ 保持向后兼容
- ✅ 逐步迁移，小步快跑
- ✅ 每次迁移后立即测试
- ✅ 更新文档

#### ❌ DON'T（不应该做的）

- ❌ 一次性迁移大量代码
- ❌ 破坏现有功能
- ❌ 忽略编译警告
- ❌ 跳过测试步骤
- ❌ 创建循环依赖
- ❌ 忘记更新文档

## ❓ 常见问题

### Q1: 编译错误 "无法找到头文件"

**原因**: include 路径不正确

**解决方案**:
1. 检查 Build.cs 中的 PublicIncludePaths
2. 更新 include 语句
3. 确保模块依赖正确

### Q2: 链接错误 "无法解析的外部符号"

**原因**: 模块导出宏不正确

**解决方案**:
1. 检查 AURACORE_API 等宏定义
2. 确保类声明中包含导出宏
3. 检查 Build.cs 中的依赖关系

### Q3: 插件加载失败

**原因**: 插件描述文件配置错误

**解决方案**:
1. 检查 .uplugin 文件格式
2. 确保模块名称正确
3. 检查插件依赖关系

### Q4: 循环依赖错误

**原因**: 插件之间存在循环依赖

**解决方案**:
1. 重新设计插件架构
2. 将共享代码移到 AuraCore
3. 使用接口解耦
